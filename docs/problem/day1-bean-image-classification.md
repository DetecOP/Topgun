## 1. โจทย์และเกณฑ์

- **คะแนน Day 1 = 15% ของคะแนนรวม** มาจากภาพ test 7 ภาพ (คลาสละ 1 ภาพ ครบ 7 คลาส) คะแนน = 15 × (จำนวนภาพที่ทายถูก ÷ 7) ระบบตรวจอัตโนมัติบน Pi ของกรรมการ **ไม่คิดคะแนนความเร็ว** แต่ถ้าไฟล์ผิดรูปแบบจะได้ 0 (สไลด์หน้า 23–24)
- **Train กับ Test มีลักษณะต่างกัน** (สไลด์หน้า 8–9):
  - **Train:** 3 ภาพต่อคลาส จัดเรียงเป็น 3×3 / วงกลม / สี่เหลี่ยม เมล็ดไม่ชนกัน
  - **Test:** วางเป็นกองตามธรรมชาติ เมล็ดชิดและซ้อนกันบางส่วน ถ่ายด้วยชุดอุปกรณ์เดียวกัน (กระดาษขาว ขนาด 3072×4096 เมื่อ 9 พ.ย. 2026)
  - ข้อสังเกตจากสไลด์: เมล็ดกินพื้นที่แค่ราว 1,000 px กลางภาพ ถ้าย่อทั้งภาพเหลือ 640 px เมล็ดจะเหลือราว 30 px **ต้อง crop บริเวณเมล็ดก่อน**
- สไลด์แนะนำแนวทาง B: **แยกเมล็ดด้วย OpenCV → crop ทีละเมล็ด → จำแนก → โหวต** ใช้ MobileNetV3-Small ที่ 160 px
- Day 2 ใช้ train set ชุดเดิมแต่เป็นงาน detection/segmentation บนภาพกอง ส่วน Day 3 เป็นกองที่มีหลายคลาสปนกันและต้องรันระบบเต็มบน Pi **ดังนั้นส่วนแยกเมล็ดและตัวสร้างกองจำลองที่ทำวันนี้ต้องใช้ต่อได้ใน Day 2–3**

## 2. ข้อมูล train (ตรวจเองแล้ว)

| สิ่งที่พบ | ผลต่อการออกแบบ |
|---|---|
| 21 ภาพ แต่ละภาพมีเมล็ดคลาสเดียว 8–9 เมล็ด รวมราว 175 เมล็ด หรือราว 25 เมล็ดต่อคลาส | ต้องเทรนรายเมล็ด และต้อง augment หนัก |
| พื้นกระดาษขาว มีแสงไม่สม่ำเสมอและขอบภาพมืด | ตัดเมล็ดด้วยวิธีคลาสสิกได้ ต้นแบบ (LAB distance → threshold → close → fill) ได้ 7–10 ชิ้นต่อภาพ แต่เมล็ดที่ติดกันยังรวมเป็นชิ้นเดียว |
| ที่ความละเอียด 1536 px เมล็ดยาวราว 140–180 px (ราว 280–360 px ที่ความละเอียดเต็ม) | crop ที่ 128–160 px พอ |
| **ภาพ `husk`, `broken` และ `black/circle` มีขนาดไฟล์ราว 130–160 KB และไม่มี EXIF** ส่วนภาพอื่นราว 2.5 MB | **เสี่ยง shortcut** โมเดลอาจเรียนจาก artifact ของการบีบอัด ต้อง re-encode JPEG ที่คุณภาพสุ่มตอน train ทุก crop |
| คู่ที่สับสนง่ายตามสไลด์หน้า 5: good↔immature/parchment, shell↔broken, black↔husk, broken↔immature | ต้องใช้ทั้งสีและรูปทรง จึงควรเก็บขนาดจริงของเมล็ดไว้ (ไม่ resize ให้เต็มกรอบทุกเมล็ด) |

## 3. Architecture

### หัวใจ: **ตัวสร้างกองจำลอง (synthetic pile)** เพราะ test เป็นกองแต่ train เป็นภาพจัดเรียง

```
TRAIN (GPU server)
21 ภาพ ─► segment (แยกได้ง่ายเพราะเมล็ดไม่ชนกัน) ─► bean cut-outs + alpha mask (~175 ชิ้น พร้อม label)
         ─► PileSynth: สุ่มวางเมล็ดคลาสเดียวกัน 10–30 เมล็ดบนพื้นกระดาษจริงที่ลบเมล็ดออกแล้ว
                       หมุน/สเกล ±10%, ซ้อนกัน 0–40%, เพิ่มเงา, สุ่มคุณภาพ JPEG
                       (ได้ instance mask ฟรี ใช้ train detector ของ Day 2 ได้ทันที)
         ─► สร้าง patch ด้วยวิธีเดียวกับตอน infer ─► fine-tune CNN
         ─► CV: แยก cut-out ตามภาพต้นทาง (leave-one-layout-out 3 fold) แล้ววัดผลบนกองจำลองที่สร้างจาก fold ที่กันไว้

INFER (Pi, onnxruntime, ไม่มี torch)
ภาพ ─► decode แบบ draft (DCT 1/2) + exif_transpose
    ─► foreground mask ─► crop ROI รอบกองเมล็ด
    ─► เส้นทาง 1: distance transform + watershed ─► crop รายเมล็ด
       เส้นทาง 2: sliding window ขนาดเท่าเมล็ดบน foreground (ทนต่อเมล็ดที่ซ้อนกัน)
    ─► ส่งทุก patch เข้า ONNX ใน batch เดียว ─► เฉลี่ย log-prob ─► คลาสของภาพ
    ─► (ถ้าได้รับอนุญาต) Hungarian assignment 7 ภาพ ↔ 7 คลาส
    ─► เขียน CSV + คัดลอกภาพเข้าโฟลเดอร์คลาส, ตรวจรูปแบบ CSV ก่อนจบ, exit code ตาม spec
```

ทำไมใช้ทั้งสองเส้นทาง: ภาพแบบกองทำให้ watershed แยกเมล็ดพลาดได้ แต่โจทย์ต้องการแค่ "คลาสเดียวต่อภาพ" การเก็บ patch จำนวนมากแล้วโหวตจึงทนต่อการแยกเมล็ดผิดได้ดีกว่า

### โมเดล

| ชื่อ | รายละเอียด | หมายเหตุ |
|---|---|---|
| M1 | MobileNetV3-Large หรือ EfficientNet-B0 ที่ 160 px fine-tune แบบ 2 ขั้น (freeze ก่อนแล้วค่อยปลด) ตามสไลด์หน้า 14 | **ความเร็วไม่มีผลต่อคะแนน** จึงเลือกตัวที่แม่นกว่า MobileNetV3-Small ได้ |
| M2 | DINOv2-S แบบ frozen + LogReg (เป็น teacher หรือตัวเทียบ) | ใช้ถ้า CV ดีกว่าชัดเจนและรันบน Pi ทันเวลา |
| ENS | ใช้โมเดลจาก 3 fold เฉลี่ยกัน | ไม่นับเป็น TTA เพราะไม่ได้ augment ภาพ ทำให้นิ่งขึ้นเมื่อข้อมูลน้อย |

- **Augment:**
  - หมุน 0–360°, flip
  - scale ±10% (ไม่ใช้ RandomResizedCrop แรงๆ เพราะขนาดเมล็ดเป็นสัญญาณของคลาส broken และ husk)
  - ColorJitter เบาๆ (hue ≤ 0.02)
  - blur
  - JPEG ที่คุณภาพสุ่ม 30–95
  - เปลี่ยน white balance ±5%
- loss: CE + label smoothing 0.1 และ class-balanced sampler

### Pi 4 4GB + ONNX Runtime

- `requirements.txt` (สำหรับ infer): `onnxruntime`, `numpy`, `pillow`, `opencv-python-headless` (**ไม่มี torch**)
- onnxruntime มี wheel สำหรับ aarch64 (OS 64-bit) แผนสำรองถ้า pip ใช้ไม่ได้หรือเป็น 32-bit:
  - ใช้ `cv2.dnn.readNetFromONNX` ด้วยไฟล์ ONNX เดิม
  - `infer.py` ตรวจและสลับให้อัตโนมัติ
- ตั้งค่า SessionOptions: `intra_op_num_threads=4`, `ORT_ENABLE_ALL`, สร้าง session ครั้งเดียว, ใช้ batch แบบ dynamic
- decode ด้วย `Image.draft('RGB', (1536, 2048))` แล้วตามด้วย `exif_transpose` ต้องทดสอบกับภาพที่ไม่มี EXIF ด้วย
- งบเวลา **(ประมาณ)**: ไม่เกิน 2 s ต่อภาพบน Pi 4 แม้ไม่คิดคะแนนความเร็วก็ไม่ควรช้าจนเกิด timeout
- weights: ต้องโหลดได้จาก path ที่ส่งเข้ามา รายละเอียดชื่อไฟล์ดูคำถามข้อ 3

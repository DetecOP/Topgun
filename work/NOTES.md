## 🎯 คอนเซ็ปต์ของทีม (ทิศทางของงานทั้งหมด)
**"ขายอัตโนมัติทั้งหมด ขายให้เร็วที่สุด ขายล่วงหน้าได้ก่อนข้อมูลเซ็นเซอร์จะมาถึง"**
- agent ทำงานเองทั้งรอบ: ดูตลาด → ประเมินมูลค่า → เสนอขาย → อ่านผล → ปรับ
- ยังไม่มีผลวัดความชื้น (Track 1) หรือคุณภาพ (Track 2) ก็ประเมินมูลค่าคร่าวๆ และเสนอขายได้ทันที
- พอข้อมูลจริงมาถึง ให้ปรับมูลค่าและราคาของรอบถัดไป

ต้องเช็กกับกติกาจริงวันที่ 17 (เพิ่มในคำถามแล้ว):
- ส่งข้อเสนอก่อนมีผลวัดได้ไหม และผลวัดมาถึงตอนไหนของรอบ
- คะแนนเทียบกับ "มูลค่าจริง" (Track 3.pdf หน้า 3) ถ้าขายเร็วแต่ประเมินผิดมากจะเสียคะแนนเท่าไร
- ความเร็วได้เปรียบจริงไหม (ใครส่งก่อนได้ก่อน หรือปิดซองพร้อมกันทุกทีม)

## 🧪 โมเดลขายล่วงหน้า (เขียนแล้ว 16 พ.ย. ตามที่ผู้ใช้สั่ง)
อยู่ใน `simulator/` ดูรายละเอียดใน [simulator/README.md](simulator/README.md)
- เป็นโครงแบบถอดเปลี่ยนสูตรได้ ส่วนประเมินมูลค่าและสูตรคะแนนยังเป็นค่าสมมติ ส่วนเรียนรู้ราคาใช้ได้เลย
- ผลทดลองแรกในตลาดสมมติ: การเรียนรู้ราคาดีกว่าบวก 8% คงที่ทุกแบบ ขายล่วงหน้าชนะชัดเมื่อของที่ขายไม่ออกถูกหักคะแนน แต่ถ้าคะแนนแบบส่วนต่าง จะสูสีกับการรอผลวัด
- DRY_RUN = True และ `submit()` ยังไม่เชื่อม API
- **อัปเดต v2 ตามงานวิจัย** ([RESEARCH.md](RESEARCH.md)): ยืมข้อมูลผู้ซื้อคนอื่น + บวกระยะเผื่อตอนขายล่วงหน้า (กัน winner's curse)
  → ขายล่วงหน้าชนะการรอผลวัดในสูตร diff (+149±55) และ penalty (+859±83) แต่แพ้เล็กน้อยในสูตร ratio (−2%)

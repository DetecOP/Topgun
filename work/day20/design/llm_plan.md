## 3. "เทรน" ในทางปฏิบัติคืออะไร (ไม่มี fine-tune)

ทำได้ 3 อย่าง ทุกอย่างอยู่ใน prompt + การวัดผล:

1. **ชุดตัวอย่าง (few-shot) จาก log จริง**
   - แหล่ง: `logs/decisions.jsonl` ด่าน 2 (P1 + R1–R8 × 3 ประเภท ≈ 27 สถานการณ์) · รอบซ้อม P1–P2 วันแข่งเพิ่มได้
   - ป้ายเฉลย (ground truth) หาแบบ "มองย้อน": ที่จุดตัดสินใจแต่ละจุด ให้ A รัน replay ต่อจากจุดนั้นด้วยชุดค่าของทุกป้าย → ป้ายที่ได้ PR สูงสุด = เฉลย (ต่างกัน < 0.001 = `normal`)
   - ใส่ใน prompt 4–6 ตัวอย่าง (ครอบทุกป้าย) · ที่เหลือเก็บไว้ทดสอบ (ห้ามใช้ชุดเดียวกันทั้งสอนและสอบ)
   - ตัวอย่างจากตลาดจำลองด่าน 3 ใช้ **สอน**ได้ แต่ **สอบ**ด้วยข้อมูลจริงเท่านั้น (ตลาดจำลองมีสมมติฐานของเราอยู่)
2. **รูปแบบ prompt ที่ลดการแปลผิด**
   - ส่งเป็นตารางตัวเลขที่ Python **ตีความแล้ว** เช่น `we_lost_last_round: yes`, `fill_last_2: [0.45, 0.48]`, `cutoff_trend: down` แทนสถานะดิบ
   - คำตอบ JSON schema: `{"COMMERCIAL": label, "INSTANT": label, "SPECIALTY": label, "note_th": "..."}` · enum ปิด · temperature 0 · max_tokens ≤ 200
   - prompt ~600–800 token (ต่ำกว่า 8,192 มาก ตอบเร็ว)
3. **การวัดผล (ทำแทนการ fine-tune)**
   - ขั้น 1 ออฟไลน์: ความแม่นป้าย LLM vs **ตัวตรวจแบบกฎ** (Python ใช้ตาราง DAY3 หัวข้อ 6 ตรงๆ) บนชุดสอบ · วัด: % ตรงเฉลย · **จำนวนครั้งที่เลือกป้ายผิดทิศ** (เช่น `shortage` ตอนที่ควร `undercut`)
   - ขั้น 2 วงปิด: replay ด่าน 2 และจำลองด่าน 3 ให้ LLM เลือกป้ายทุกรอบ (ผ่าน gateway ฝึก `:4000` ถ้ายังเปิด — **ยังไม่ทราบ** ว่าวันที่ 19 เปิดไหม) · 15 คำขอ/เกม · ≤ 20/นาที → ~1 เกม/นาที · 50 เกมพอประมาณ
   - ขั้น 3: วัด latency p95 ของ gateway ตอนรอบซ้อมวันแข่ง (56 ทีมพร้อมกัน)
   - ถ้า gateway ไม่เปิดให้ทดสอบ → **ไม่มีทางวัดขั้น 2 → ไม่เปิดงาน B ในวันแข่ง**

## 4. การต่อเข้ากับ agent (ระดับ pseudo-code · A เขียน)

```
# main.py ต่อรอบ (ลำดับเดิมตาม LLM_DESIGN ข้อ 6: ส่งซอง Python ก่อนเสมอ)
offers = strategy.decide(state, ctx)            # ราคา Python เหมือนเดิมทุกตัว
market.offer_batch(offers)                       # ส่งทันที
if LLM_MODE in ("shadow", "label"):
    facts = summarize_for_llm(model, state)       # Python ตีความสัญญาณแล้ว
    ans = llm.ask(facts, schema=LABEL_SCHEMA, timeout=min(30, seconds_left-20))
    labels = validate(ans)                        # enum ปิด · ไม่ผ่าน = normal ทุกประเภท
    labels = direction_guard(labels, model)       # ตัวกันในตาราง หัวข้อ 2
    log("llm_label", raw=ans, used=labels, rule=rule_labels(model))   # บันทึกเทียบกับกฎทุกครั้ง
    if LLM_MODE == "label":
        ctx.next_round_env = PRESETS[labels]      # มีผลรอบถัดไป ไม่แก้ซองรอบนี้
# งาน A (ปฏิทิน): ตอน SETUP ครั้งเดียว · ใช้เฉพาะเมื่อ norm_info() ตอบ calendar_format_unknown
#   ผลต้องผ่าน: จำนวนรอบ = rules.timeline.rounds · ป้ายอยู่ใน {ปกติ, เทศกาล, ใกล้ปิด, สุดท้าย} · demand_weight 0.3–3.0
#   ไม่ผ่าน = ใช้ค่าเดิมของ norm_info()
```
ค่าตั้ง: `LLM_MODE=off|shadow|label` (ค่าเริ่ม `off`) · `LLM_CALENDAR=0|1` (ค่าเริ่ม 0)

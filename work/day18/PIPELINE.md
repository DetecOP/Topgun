## 3. ภาพรวม pipeline (ต่อยอด starter · แก้ strategy.py เป็นหลัก)

```
 main.py (มีแล้ว: ลูป · phase · ไม่ล้ม · รีสตาร์ทได้)
   │  GET /v1/state ทุก ~1 วิ
   ▼
 [S1 ประเมิน]  APPRAISAL → GET /v1/calendar → TV ทุกล็อต → POST /v1/appraisals (ครั้งเดียว · ส่งทันที)
   ▼
 [S2 คัดคู่]   ล็อต × RFQ ที่ผ่านสเปก + margin กัน noise  → candidates
   ▼
 [S3 โมเดลตลาด] memory → ต่อผู้ซื้อ: เพดานประมาณ, จุดตัดการแข่ง, fill rate   (Python ล้วน)
   ▼
 [S4 จำนวน]    งบกระสอบรอบนี้ = min(capacity_left, pace × demand_weight ของ calendar)
   ▼
 [S5 ราคา]     ratio ต่อ candidate = min(เพดาน − m1, จุดตัด − m2) · บันได 2 ขั้น · พื้นราคา
   ▼
 [S6 LLM (ถ้ามี gateway)]  เสนอปรับ ratio ±0.03 และ "ขายเยอะ/เก็บ" + เหตุผลสั้น  → Python บีบให้อยู่ในกรอบ
   ▼
 [S7 guard]    kg×60 · ≤ RFQ · ≤ ล็อตเหลือ · ≤ capacity · สเปก · ratio ในช่วงปลอดภัย
   ▼
 POST /v1/offers:batch (replace_existing=true) → BATCH_REJECTED? ตัดรายการผิดตาม allowed.errors แล้วส่งซ้ำ 1 ครั้ง
   ▼
 [S8 เรียนรู้]  รอบถัดไป: last_results → memory → อัปเดตโมเดล · log ทุกการตัดสินใจ (logs/decisions.jsonl)
```

## 4. รายละเอียดแต่ละขั้น

### S1 ประเมินมูลค่า (20 คะแนนของด่าน · ส่งได้ครั้งเดียว)
- TV = สูตรจาก `rules` ใน `/v1/calendar` (appraisal.py มีแล้ว · ตรงกับ Excel และเฉลยเมื่อวาน MAPE 0)
- วันนี้ตัวอย่างมี noise → TV จากตัวอย่างอาจคลาดจากค่าจริง โดยเฉพาะล็อตที่ defect ชิดขั้นเกรด (≤1, 3, 5, 7, 15)
- แผน: ซ้อมในตลาดฝึก → ดู reveal (`/v1/sandbox/reveal`) เทียบ sample กับ true → ถ้าเห็นรูปแบบชัด (เช่นชิดขั้นแล้วคลาดเกรด) ค่อยปรับ
  **ถ้าไม่เห็นรูปแบบ ใช้ TV(sample) ตรงๆ** (ห้ามเดา noise)

### S2 คัดคู่ล็อต × RFQ (กัน SPEC_MISMATCH)
- ผ่านสเปกแบบมี margin: `defect ≤ max − Δd`, `moisture ≤ max − Δm`, `screen ≥ min + Δs`
- Δ เริ่มที่ 0 แล้ววัดจากตลาดฝึก: ขนาด |sample − true| ใน reveal → ตั้ง Δ ≈ ความคลาดทั่วไป
- ล็อตชิดขอบที่ไม่ผ่าน margin → ส่งให้ผู้ซื้อสเปกหลวมกว่าแทน (Specialty → Commercial → Instant)
- ล็อตที่ไม่ผ่านผู้ซื้อรายไหนเลย → ไม่ส่ง (เหลือ = 0.80×TV)

### S3 โมเดลตลาด (หัวใจ · Python ล้วน · ไฟล์ใหม่ `market_model.py`)
เก็บต่อ **ผู้ซื้อแต่ละราย** (persona) และสรุปต่อประเภท:

| ค่า | อัปเดตจาก | ใช้ทำอะไร |
|---|---|---|
| `ceil_lo` / `ceil_hi` | ACCEPTED (ขายได้ ×สูงสุด) / ABOVE_LIMIT (×ต่ำสุด) | เพดานประมาณ = กึ่งกลาง · ห้ามเสนอเกิน |
| `clear_lo` / `clear_hi` | ACCEPTED / OUTBID | จุดตัดการแข่ง = ราคาที่ชนะได้ |
| `fill` | market_summary: bought / wanted | fill < 0.9 = ติดเพดาน (ขายได้ถ้าไม่เกินเพดาน) · fill = 1 และข้อเสนอ > ต้องการ = แข่ง (ต้องตัดราคา) |
| `crowd` | offers / (wanted ในหน่วยกระสอบ) | ยิ่งสูงยิ่งต้องลด |

ค่าเริ่มต้น (prior) ×TV — ใช้จนกว่าจะมีผลจริงในเกมนั้น:

| ประเภท | เพดาน prior | จุดตัด prior (ตลาดแข่ง) | ratio เริ่ม |
|---|---|---|---|
| SPECIALTY | **ยังไม่ทราบ** (< 1.60) | ยังไม่ทราบ | 1.15 แล้วเรียนจากผล (ซ้อมก่อนในตลาดฝึก) |
| COMMERCIAL | 1.04–1.10 | 0.98–1.00 | 0.985 |
| INSTANT | 0.94–0.98 | ติดเพดานเป็นหลัก | 0.95 |

~~กฎอัปเดต ±0.01 เท่ากันทุกครั้ง~~ (v1) → **v2: เก็บเป็นขอบเขต + ความมั่นใจ**

ผลแต่ละซองบอก "ขอบ" ไม่ใช่ "ค่า" (ข้อมูลถูกตัด / censored):
| สถานะที่ ratio = r | บอกเรื่องเพดาน | บอกเรื่องจุดตัด (ราคาที่ชนะได้) |
|---|---|---|
| ACCEPTED | เพดาน ≥ r | จุดตัด ≥ r (ชนะได้ที่ r) |
| PARTIAL | เพดาน ≥ r | จุดตัด ≈ r (ขอบพอดี) — **ข้อมูลคุณภาพสูงสุด** |
| OUTBID | เพดาน ≥ r | จุดตัด < r |
| ABOVE_LIMIT | เพดาน < r | – |
| SPEC_MISMATCH | – | – (ข้อมูลเรื่องคุณภาพจริง → ส่งให้ cliff_risk) |

- เก็บต่อผู้ซื้อ: `observed` (ขอบที่เห็นจริง) · `estimate` (ค่ากลางที่ใช้) · `n` + ความกว้างช่วง = **ความมั่นใจ**
- ขั้นการปรับ = ใหญ่เมื่อข้อมูลน้อย/ช่วงกว้าง (0.02) → เล็กเมื่อมั่นใจ (0.005) · ไม่กระโดดเกินครึ่งช่วงที่เหลือ
- ข้อมูลขัดกัน (เช่น ACCEPTED ที่ 1.00 แล้ว ABOVE_LIMIT ที่ 0.98 คนละ RFQ) = เพดานแกว่งราย RFQ → **ไม่ลบข้อมูล** แต่ขยายความกว้าง (spread) และลดความมั่นใจ
- ใช้ `market_summary` ประกอบ: fill (bought/wanted) และ offers/กระสอบ ของทุก RFQ แม้เราไม่ได้ส่ง → รู้ว่า RFQ แบบนี้ "แข่ง" หรือ "ติดเพดาน"
  (`price_min/max/avg` เป็นราคาของข้อเสนอทั้งหมดหรือเฉพาะที่ถูกซื้อ: **ยังไม่ทราบ** → ตรวจจาก probe_data ก่อนใช้)
- ขายได้ไม่ได้แปลว่าตั้งถูก: ACCEPTED ทั้งหมดหลายรอบติด = ยังต่ำกว่าจุดตัด → ส่วนหยั่ง (Exploration) ขยับขึ้น
- เกมใหม่ในตลาดฝึก → เริ่มจาก prior ปรับด้วยค่าเกมก่อน แต่ลดความมั่นใจลง (ตลาดแข่งอาจต่างจากตลาดฝึก)

### S4 จำนวนกระสอบต่อรอบ (sell_budget)
- งบรวมรอบนี้ = `min(capacity_left_kg/60, ceil(เหลือทั้งหมด / รอบที่เหลือ × PACE × demand_weight))`
  - `demand_weight` จาก calendar (รอบเทศกาล/Specialty มาก → ขายมากขึ้น · รอบซบ → ขายน้อยลง)
  - PACE เริ่ม 1.3 (ค่า starter) · capacity จำกัดราว 1.5× อยู่แล้ว → รอบท้ายเทไม่ได้ ต้องขายสม่ำเสมอ
- แบ่งงบให้ล็อตตาม "เงินต่อกระสอบที่คาดว่าได้" = TV × ratio ที่น่าจะชนะ × โอกาสขายได้
- ลำดับผู้ซื้อ: จ่ายสูงก่อน (Specialty > Commercial > Instant) แต่ **ภายในกลุ่มสุ่มถ่วงด้วยขนาด RFQ** (สไลด์ 22) กันชนกับทีมอื่นที่ใช้ starter เดียวกัน
- ~~ต่อ RFQ ไม่เกิน ~30%~~ → **v2 จัดสรรตามคะแนนโอกาส** (ค่าทดลอง):
  `score = P(ขายได้) × (ratio − 0.80) × TV` (กำไรเหนือของเหลือ ตามสูตร PR)
  | คะแนนโอกาส | ส่วนของ RFQ ที่เราเสนอ |
  |---|---|
  | สูง (ติดเพดาน fill < 0.9 และเราอยู่ใต้เพดานมั่นใจ) | 40–50% |
  | กลาง | 20–30% |
  | ต่ำ (แข่งหนัก crowd สูง) | 5–15% |
  แล้วบีบด้วย `capacity_left_kg` และ kg ของ RFQ เสมอ
- **Opportunity Cost**: เรียงการจัดสรรจากล็อตที่ "ทางเลือกน้อย" ก่อน (ผ่านสเปกผู้ซื้อน้อยราย) ·
  ล็อตเกรดสูงไม่เทให้ Instant ถ้ายังมี Specialty/Commercial ที่ผ่านและจ่ายมากกว่า ·
  ถ้า calendar บอกว่ารอบข้างหน้าต้องการมาก → สงวนกระสอบบางส่วนไว้ (แต่ไม่เกินที่ capacity รอบนั้นรับไหว)
- **Lot × Buyer** เลือกด้วย "ค่าคาดหวัง" ไม่ใช่ "ราคาสูงสุด": ผู้ซื้อจ่ายสูงแต่สเปกตึงกับล็อตเสี่ยง → P(SPEC_MISMATCH) สูง → คะแนนต่ำ

### S5 ราคา (rule_plan)
- ตัวคูณต่อประเภท (C 0.985 · I 0.95 · S 1.15) = **prior สำหรับรอบแรกเท่านั้น** (S = สมมติฐาน รอข้อมูล Specialty)
- ต่อ RFQ: `ratio = min(ceil_est − m1, clear_est − m2)` แล้วบีบ `[floor, ceil_est]`
  - m1, m2 กว้างขึ้นเมื่อความมั่นใจต่ำ · แคบลงเมื่อมั่นใจ
  - ปรับตามบริบท RFQ: crowd สูง → ลด · fill ต่ำ (ติดเพดาน) → ราคาเกือบเพดาน · ของเหลือเยอะ/รอบเหลือน้อย → ลด · ช่วงเกม (3.5)
- **เลี่ยงเลขกลม**: ทุกทีมที่ใช้ starter จะตั้ง 1.00 → เราตั้ง 0.995/0.985 ได้คิวก่อนทั้งก้อน (เท่ากันพอดี = แบ่งกระสอบ)
- **บันได 2 ขั้น** ต่อผู้ซื้อ: 60% ของงบที่ราคาปลอดภัย · 40% ที่ +0.02 (หาเพดาน/จุดตัด) · ใช้คนละ RFQ หรือคนละล็อต
- พื้นราคา: COMMERCIAL ≥ 0.95 · SPECIALTY ≥ 1.00 · INSTANT ≥ 0.88 · รอบสุดท้าย ≥ 0.86 (ของเหลือ = 0.80)

### S6 LLM (เปิดเมื่อรู้ที่อยู่ gateway · ไม่อยู่บนเส้นทางวิกฤต) · รายละเอียดเต็ม: [LLM_DESIGN.md](LLM_DESIGN.md)

## 4.5 จุดเสี่ยง: ค่าที่ติดขอบเกรด (ค่าเปลี่ยนแรงเป็นขั้นบันได)

สูตร TV ไม่ต่อเนื่อง ข้ามขอบนิดเดียว (0.01) มูลค่ากระโดด · วันนี้ตัวอย่างมี noise → **ล็อตที่ค่าชิดขอบ เกรดจริงอาจอยู่อีกฝั่ง**
คำนวณจาก rules ตลาดฝึก (p0 = 120, ตัวอย่างฐาน defect 2 / moisture 11 / screen 15):

| ขอบ | ข้ามขอบแล้ว TV เปลี่ยน | ความรุนแรง | ผลเรื่องสเปกผู้ซื้อ |
|---|---|---|---|
| defect 1 → เกิน 1 (PREMIUM → GRADE_1) | −3.7% | กลาง | – |
| defect 3 (GRADE_1 → GRADE_2) | −3.9% | กลาง | – |
| defect 5 (GRADE_2 → GRADE_3) | −4.0% | กลาง | – |
| **defect 7** (GRADE_3 → BELOW_STANDARD) | **−11.5%** | สูง | **หลุดสเปก Commercial (≤ 7)** |
| **defect 15** (BELOW_STANDARD → REJECT) | **−29.4%** | สูงมาก | **หลุดสเปก Instant (≤ 15)** → ขายใครไม่ได้ |
| moisture 12.5 | ~0% (สูตรต่อเนื่อง) | ต่ำต่อ TV | **หลุดสเปก Commercial (≤ 12.5)** (ล็อต 4 เมื่อวาน 12.7 โดนจุดนี้) |
| moisture 14 | ~0% | ต่ำต่อ TV | **หลุดสเปก Instant (≤ 14)** |
| **moisture 15** | **−34.9%** (factor → 0.60) | สูงมาก | – |
| screen 12↔13 / 13↔14 / 15↔16 / 17↔18 | +5.4% / +3.1% / +3.0% / +2.9% | กลาง | Specialty มี min_screen (ค่ายังไม่ทราบ) |
| screen 14↔15, 16↔17 | 0% | ไม่มี | – |

### ผลกระทบ 3 ทาง
1. **คะแนนประเมิน (20):** TV ที่ส่งคลาดจากค่าจริงเป็นขั้น → MAPE พุ่ง (ขอบ 7 คลาด 11.5% = เกิน 10% = ได้ 0 สำหรับล็อตนั้น)
2. **ราคาขาย:** ผู้ซื้อเรียงและตัดเพดานด้วย ราคา ÷ TV **จริง** · ถ้าเกรดจริงต่ำกว่าที่เราคิด ratio จริงของเราสูงขึ้นทันที → ABOVE_LIMIT / OUTBID
   (เช่น ล็อต defect 6.9 คิดว่า GRADE_3 เสนอ ×0.98 · ถ้าจริง 7.1 ratio จริง ≈ ×1.11 → เกินเพดาน Commercial แน่)
3. **สเปก:** ค่าชิดขอบสเปก (defect 7/15, moisture 12.5/14, min_screen) → SPEC_MISMATCH เสียรอบฟรี

### กฎใน agent
- ฟังก์ชันใหม่ `cliff_risk(sample, rules, Δ)` คืน: ขอบที่ใกล้สุด · TV ถ้าค่าเลื่อน ±Δ (`tv_lo`, `tv_hi`) · สเปกที่อาจพลิก → log ทุกล็อตตอนเริ่มเกม
- **Δ (ความกว้างโซนเสี่ยง) วัดจาก reveal ในตลาดฝึก** (|sample − true| ของแต่ละค่า) · ก่อนวัดได้ = ยังไม่ทราบ ใช้ค่าตั้งต้นระวังไว้ก่อน เช่น defect ±0.5, moisture ±0.3, screen ±1 แล้วแก้ตามที่วัดได้
- **ประเมิน:** ถ้า noise สมมาตรและไม่เอียง ค่าที่ทำ MAPE ต่ำสุดคือ TV(sample) (ค่ากลาง) → ส่ง TV(sample) ·
  ถ้า reveal แสดงว่า noise เอียงข้างใดข้างหนึ่ง จึงค่อยเลื่อน (ห้ามเดาก่อนเห็นข้อมูล)
- **ขาย:** ล็อตในโซนเสี่ยงคิดราคาจาก `tv_lo` (ฝั่งเกรดต่ำ) แทน TV · ยอมเสียเงินเล็กน้อยถ้าจริงๆ เกรดดี ดีกว่าโดนปัดทั้งซอง
- **สเปก:** ล็อตในโซนเสี่ยงของขอบสเปก ห้ามส่งให้ผู้ซื้อที่สเปกนั้นตึง → ส่งผู้ซื้อสเปกหลวมกว่า (Specialty → Commercial → Instant)
- ถ้าโดน SPEC_MISMATCH จริง → จำคู่ (ล็อต, ประเภทผู้ซื้อ) แล้วไม่ส่งซ้ำทั้งเกม
- ทุกทีมได้ล็อตเดียวกัน noise เดียวกัน → ทีมที่ไม่ระวังขอบจะโดนปัด/คลาดพร้อมกัน = โอกาสของเรา

เลือกด้วยกฎ Python ที่อ่านได้ · LLM (ถ้ามี) ช่วยบอกได้ว่าเห็นสถานการณ์ไหน แต่ Python เป็นคนเลือกค่าในกรอบ

**③ แผนที่ไม่พังทุกแบบ (robust) + วางแผนล่วงหน้าทุกรอบ**
- ทุกรอบวางแผนกระสอบ **ทั้งรอบที่เหลือ** (ใช้ calendar + ราคาคาดหวังแต่ละรอบ) แต่ส่งจริงแค่รอบนี้ แล้วคิดใหม่รอบหน้าเมื่อมีข้อมูลใหม่ (receding horizon)
- ก่อนแข่ง: รันแผนกับคู่แข่งจำลองหลายแบบใน simulator ของเรา (`work/simulator/` arena 80+ กลยุทธ์ · หลาย seed) →
  เลือกชุดค่าที่ PR "แย่สุด" ยังดี ไม่ใช่ชุดที่ "ดีสุด" ในแบบเดียว

## 4.7 ให้เป็นเกมของเรา + คิดหลายขั้น (คู่แข่งเดาไม่ได้)

**หลักการ:** เราบังคับตลาดไม่ได้ (ผู้ซื้อ/เพดานมาจากเซิร์ฟเวอร์ · เราเป็น ~1/56 ของของ · ห้ามนัดราคา) แต่
**คาดว่าคนอื่นจะทำอะไร แล้วยืนตรงที่เขาไม่อยู่ — ราคา ผู้ซื้อ จังหวะ**

**ก. อ่านทีม starter (สถานการณ์ C ใน 4.6)** ค่าเริ่ม starter ที่รู้แน่: ×1.00 ทุกที่ · PACE 1.3 · สุ่ม RFQ ถ่วงขนาด · LLM เสนอน้อย
- คาด: กองข้อเสนอที่ ×1.00 · Instant (เพดาน < 1.00) ทีม starter โดน ABOVE_LIMIT → ช่องว่างใต้เพดาน
- สัญญาณตรวจ: OUTBID ของเราที่ ≥ 1.00 แต่ ACCEPTED ที่ 0.99 · fill ของ Instant < 0.9 ทั้งที่ข้อเสนอเยอะ
- **เป็นสมมติฐาน** ถ้าข้อมูลไม่ตรง playbook จะไม่เลือกสถานการณ์นี้เอง

**ข. คิดหลายขั้น (level-k)**: ขั้น 0 ×1.00 → ขั้น 1 ×0.99 → ขั้น 2 ×0.98 → … → หนีไป Instant → Instant แน่น → กลับ Commercial → …
ข้อสรุป: **ไม่มีตัวคูณเดียวที่ชนะได้ตลอด** (มีคนลึกกว่า 1 ขั้นเสมอ) และคิดลึกเกินคนจริง (ส่วนใหญ่ขั้น 0–2) = ขายถูกเปล่าๆ

**ค. กฎที่ใช้จริงใน agent**
1. **บันไดราคาหลายขั้นต่อรอบ**: แบ่งกระสอบเป็น 3–4 ขั้นรอบราคาเป้า (เช่น −0.010 / 0 / +0.010 / +0.025 สำหรับส่วนหยั่ง) → กองอยู่ขั้นไหนก็มีส่วนชนะ + รู้ว่ากองอยู่ตรงไหน
2. **สุ่มเล็กน้อยในกรอบปลอดภัย**: ±0.004 ต่อซอง · เลขไม่กลม (เลี่ยง ×.x00 และ ×.x50 ของราคาบาท)
3. **สุ่ม RFQ ถ่วงคะแนนโอกาส**: ไม่ทุ่มที่ RFQ ดีสุดที่เดียว
4. **ตามข้อมูลไม่ตามการเดา**: ขั้นล่างสุดของบันไดแพ้ → เลื่อนทั้งบันไดลง · ขั้นบนสุดชนะ → เลื่อนขึ้น
5. **เส้นที่ไม่ข้าม**: พื้นราคาต่อประเภท ถ้าทุกทีมตัดราคาลงต่ำกว่าพื้น → เก็บของ (ของเหลือ = 0.80×TV · รอบหน้าอาจดีขึ้น)

**ง. ไม่ทำ**: ข้อเสนอหลอกเพื่อปั่น market_summary (กิน capacity · `price_*` อาจไม่นับข้อเสนอที่ไม่ถูกซื้อ = ไม่มีผล ·
เสี่ยงโดนตีความว่าปั่นตลาดตอนกรรมการตรวจโค้ด 5 ทีมแรก) · นัด/แลกข้อมูลกับทีมอื่น (ผิดกติกาตรง)

ทำไมคู่แข่งเล็งเราตรงๆ ไม่ได้: ข้อเสนอปิดผนึก · เห็นแค่ภาพรวมรายรอบที่ปน 56 ทีม → ความเสี่ยงจริงคือ "เรายืนในกองโดยไม่รู้ตัว" ไม่ใช่ "โดนจับทาง"

## 4.8 แรงกดดันกระสอบ (Supply Pressure) — บริหารตามของที่มีเทียบกับที่ขายได้

`pressure = กระสอบที่ขายได้ที่เหลือ ÷ (capacity ต่อรอบ × รอบที่เหลือ)` · คำนวณใหม่ทุกรอบ
capacity ต่อรอบ = `round_capacity_kg` จาก state · ถ้าตลาดไม่จำกัด (null) ใช้ 1.5 × ส่วนเฉลี่ย (ตามสไลด์ 18) เป็นตัวแทน
ตอนเริ่มเกม pressure ≈ 1/1.5 = 0.67 · ขายช้ากว่าแผน → สูงขึ้น · ขายเร็ว/ของน้อย → ต่ำลง

| โหมด | pressure | ความหมาย | ปรับอะไร (ค่าทดลอง) |
|---|---|---|---|
| **ของน้อย (scarce)** | < 0.40 | ไม่ต้องรีบ ทุกกระสอบมีค่า | ส่วนหยั่ง ≤ 1 กระสอบ/รอบ · บันได [0, +0.01] (ไม่มีขั้นต่ำ) · พื้นราคา +0.02 · ปริมาณ ×0.8 · ไม่ใช้คู่รอง (ผู้ซื้อจ่ายต่ำ) ก่อนช่วงท้าย |
| **ปกติ** | 0.40–0.80 | ตามแผน | ค่าเดิม |
| **ของล้น (flood)** | > 0.80 | ขายไม่ทัน capacity จะเหลือ 0.80 | บันได [−0.015, −0.005, +0.005] · ส่วนหยั่งครึ่งเดียว · ปริมาณ ×1.2 · พื้นราคาแบบช่วงท้าย (≤ 0.90) |
รอบสุดท้ายไม่ใช้ pressure (ขายทั้งหมดที่ขายได้)
ลำดับล็อต: คะแนน = P(ขาย) × (ratio − 0.80) × TV อยู่แล้ว → ล็อตที่ได้ "เหนือของเหลือ" มากสุดได้ขายก่อน

## 4.14 งบกระสอบตามอัตราขายได้จริง (โค้ด pace3 · 18 พ.ย. ~12:00)

ผล TestNew (spec2 · ตลาดแบบใหม่ 36 เกม): PR 0.943 · ได้ที่ 1 56% · Top5 81% · แต่ **ของขายได้เหลือ 0.017 PR (30% ของที่หาย)** ·

**แก้:** กระสอบที่เสนอ = กระสอบที่อยากให้ขายได้ ÷ อัตราขายได้จริงของเกมนี้ (ค่าเริ่ม 0.6 · บีบ 0.4–1.0) ·

**ตรวจ (ออฟไลน์):** เล่นซ้ำรอบจริงของ TestNew: ใช้ capacity 6 ล็อต 83% → 93% · 5 ล็อต 82% → 90% · 4 ล็อต 75% → 85% · เกิน capacity 0 ·

**ผลตลาดฝึก (12:20):** pace3 vs เดิม PR\* 0.961 vs 0.960 (แยกไม่ออก) · ของเหลือ 0.016 vs 0.025 · แต่ขายต่ำกว่ามูลค่า 0.023 vs 0.015 ·

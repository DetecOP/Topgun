# day17 · ผู้ช่วยขายมือ v2 (ตามกติกาจริงจากสไลด์วันที่ 17)

⚠️ **ช่วง 1 ยื่นซองด้วยสคริปต์/โค้ด = คะแนน 0** → เครื่องมือนี้คำนวณ/แนะนำเท่านั้น คนกดยื่นในหน้า `/trade` เอง

## แบ่งงาน
| ผู้ใช้ | Claude |
|---|---|
| ส่งภาพหน้าจอ: การ์ด "ล็อตของฉัน" (ต้นเกม) และ "คำขอซื้อ (RFQ) รอบนี้" (ทุกรอบ) | กรอก `state.json` แล้วรันคำสั่ง |
| กรอก TV ในช่อง "ส่งผลประเมิน" แล้วกดส่ง (ภายใน 10 นาทีแรก) | `tv` → ตาราง TV ทุกล็อต (ตรงกับ Excel ผู้จัด) |
| ยื่นซองตามตาราง | `suggest` → RFQ · ล็อต · กระสอบ · ราคา · เหตุผล |
| ส่งภาพหน้าจอ "ผลรอบล่าสุด" | `result` → บันทึก ปรับ markup รอบหน้า เขียน rounds.csv |

## คำสั่ง (จากโฟลเดอร์ work)
```powershell
copy day17\state_template.json day17\state.json      # เริ่มเกมใหม่
.venv\Scripts\python.exe day17\sell_helper.py tv
.venv\Scripts\python.exe day17\sell_helper.py suggest
.venv\Scripts\python.exe day17\sell_helper.py result R1-01=A R1-02=L R1-03=O R1-04=P2
.venv\Scripts\python.exe day17\sell_helper.py status
```
ผล: `A` ขายได้หมด · `P<n>` ขายได้ n กระสอบ · `O` OUTBID · `L` ABOVE_LIMIT · `S` SPEC_MISMATCH
(ถ้า RFQ เดียวยื่นหลายล็อต ใช้ `R1-01:LOT-T05-1=A`)

## หลักที่ใช้
1. **TV** = 120 × G × M × S (สูตรเปิดเผย) — ทดสอบตรงกับเฉลยสไลด์ 119.75 / 104.04 / 119.40
2. **markup = ราคา ÷ TV** คือสิ่งเดียวที่ผู้ซื้อดู → หาเพดานลับต่อผู้ซื้อแบบแบ่งครึ่ง (ขายได้ ↔ ABOVE_LIMIT) · OUTBID → ถูกกว่าเดิม
3. ผู้ซื้อใหม่ประเภทเดียวกันลองคนละราคา (สำรวจ) · แบ่งกระสอบให้หลาย RFQ ที่จ่ายใกล้กัน
4. ล็อตที่ไปได้ทางเดียว (เช่น ชื้นเกิน 12.5 → Instant เท่านั้น) ได้จัดก่อน · ล็อตที่ไม่มีใครรับ → ปล่อยขาย 0.8×TV
5. ไม่ต่ำกว่า ×0.85 · รอบสุดท้ายลดให้ขายออก (ของเหลือได้แค่ ×0.80)

ค่าเริ่มต้น markup (Commercial ×1.10, Instant ×1.02) **เป็นสมมติ** ปรับใน `state_template.json` → `start_markup`
